## API

The `HfApi` table a mod's `hellforge_mod_init(const HfApi* hf, HfMod* mod)` receives. Functions are only ever added at
the end, and a mod checks `hf->version` to know which ones the loader has. Each section lists what one SDK version
added, in table order; a version that added nothing to the table has no section. Each entry gives the member's
name, its type, and its comment from `hellforge_mod.h`. Where one comment covers several members, it is on the
first of them.

See also: [Logic at run time](modding/runtime.md) for events, actions and live edits; [Content](modding/content.md)
for changing and adding content; [Hooks and game memory](modding/hooks.md) for `hook`, `find_pattern`, `read` and
`write`; [Debugging](modding/debugging.md) for the mod's log and refusals.

### SDK 1

- `version`: `uint32_t`. HF_MOD_SDK_VERSION of the loader; functions are only ever added at the end.
- `size`: `uint32_t`. sizeof(HfApi) of the loader.
- `log`: `void (HfMod* mod, const char* format, ...)`. Logging to the mod's own log in the session folder (printf format).
- `build_id`: `const char* (void)`. The supported game build ("25480438") and the mod's own id and folder (UTF-8).
- `mod_id`: `const char* (HfMod* mod)`
- `mod_folder`: `const char* (HfMod* mod)`
- `on`: `int (HfMod* mod, HfEvent event, HfEventCallback callback, void* user)`. Calls back once when the event happens (at once if it already did). Returns 0 on success.
- `module_base`: `uintptr_t (const char* module, size_t* size)`. A loaded module's base address and image size, or 0 ("game.dll", "helldivers2.exe").
- `find_pattern`: `uintptr_t (const char* module, const char* pattern)`. The first match of an IDA-style byte pattern ("48 8B ?? 24 ?? E8") in the module's image, or 0. It reads the code as it is now: a function another mod or HellForge hooked starts with a jump. To check a function before hooking it, use code_matches (SDK 13), which reads its bytes from before any hook.
- `read`: `int (uintptr_t address, void* buffer, size_t size)`. Memory: 0 on success. write makes the bytes writable for the write, restores their protection and flushes the instruction cache, so it works for code and data.
- `write`: `int (uintptr_t address, const void* data, size_t size)`
- `write_u32_if`: `int (HfMod* mod, uintptr_t address, uint32_t expect, uint32_t value)`. Writes a u32 only if it holds `expect` (or already `value`): 0 written or already set, 1 left alone.
- `hook`: `int (HfMod* mod, uintptr_t target, void* detour, void** original)`. Detours the function at `target` to `detour`; *original receives a pointer that calls the next hook in the function's chain, or its own code. 0 on success. Hooks stay for the session. Since SDK 13 every hook, a mod's or HellForge's own, joins one chain per function, so several mods can hook the same function: hook_ex (SDK 13) says the order, and this is hook_ex with priority 0. Call the original through `*original` every time, never a copy of it: HellForge rewrites it when another hook joins the chain after this one. Code another overlay already redirected (its jump stub in allocated memory, where MinHook finds no room) is chained: the stub's address becomes the detour, the overlay's code the original.
- `network_field_type`: `int (const char* name, HfFieldType* type)`. Network field types by name (after HF_EVENT_NETWORK_READY). get: 0 and *type filled, or 1. set_bits widens an integer type, only if it is exactly `expect` (or already widened): 0 on success, 1 left alone.
- `set_network_field_bits`: `int (HfMod* mod, const char* name, HfFieldType expect, int32_t bits)`
- `component_record`: `uintptr_t (const char* component, uint64_t resource, uint32_t* stride)`. The address of an entity's record of a component ("DepositComponentData") after HF_EVENT_ENTITIES_READY, or 0 when the entity owns no such record, owns several, or shares it with another entity. *stride receives the record size. Resource ids are the 64-bit entity resource hashes HD2Runtime's catalogs list.

### SDK 2

- `add_weapon`: `uint32_t (HfMod* mod, const HfWeapon* weapon)`. Adds a new arsenal weapon (see HfWeapon). HellForge adds it to the game's entity data when that loads, to the armory, and to the backend's item catalogue and the player's inventory; it behaves exactly like its base except for what the mod changes in its own records. Call it from hellforge_mod_init. Returns the new weapon's loadout id, or 0 (the mod's log says why).
- `weapon_entity`: `uint64_t (uint32_t weapon)`. The entity resource of a weapon any mod added (its loadout id), for component_record; 0 if there is none.

### SDK 3

- `add_projectile`: `uint32_t (HfMod* mod, const HfProjectile* projectile)`. Adds a new projectile type (see HfProjectile). Call it from hellforge_mod_init. Returns its ProjectileType (351 and up), or 0 (the mod's log says why). 64 new types in all mods together (HellForge moves the game's list).
- `projectile_row`: `uintptr_t (uint32_t type)`. The 272-byte settings row of a projectile a mod added, after HF_EVENT_PROJECTILES_READY, or 0. Its +0 is the type and must stay so; the rest may be changed (HD2Runtime's research names the members).
- `add_damage`: `uint32_t (HfMod* mod, const HfDamage* damage)`. Adds a new damage type (see HfDamage). Call it from hellforge_mod_init, before the projectiles that deal it. Returns its id (650 and up), or 0 (the mod's log says why).
- `damage_row`: `uintptr_t (uint32_t id)`. The 76-byte DamageInfo row of a damage type a mod added, after HF_EVENT_PROJECTILES_READY, or 0: +0 id (must stay), +4 standard damage, +8 durable damage, +0x0C four armour penetration values, +0x1C on status effects.
- `resource_hash`: `uint64_t (const char* name)`. The game's 64-bit id of a resource name ("my_name/my_mod/bolt"): what the game's data and rows store.

### SDK 4

- `add_stratagem`: `uint32_t (HfMod* mod, const HfStratagem* stratagem)`. Adds a new stratagem (see HfStratagem). Call it from hellforge_mod_init. Returns its StratagemType (150 and up), or 0 (the mod's log says why). The game has room for 48 new stratagems in all mods together.
- `stratagem_row`: `uintptr_t (uint32_t type)`. The 400-byte settings row of a stratagem a mod added, once the game has loaded its stratagems, or 0. +0 type and +4 stable id must stay; HD2Runtime's research names the rest (docs/internals.md "Stratagems").
- `add_entity`: `uint64_t (HfMod* mod, const HfEntity* entity)`. Adds a new entity (see HfEntity). Call it from hellforge_mod_init. Returns its resource id, or 0 (the mod's log says why). Entities and weapons share room for 64.
- `add_behaviour`: `uint32_t (HfMod* mod, const HfBehaviour* behaviour)`. Adds a new behaviour (see HfBehaviour). Call it from hellforge_mod_init. Returns its id (694 and up), or 0 (the mod's log says why). An entity given it runs its base instead if HellForge could not install it.

### SDK 5

- `add_difficulty`: `uint32_t (HfMod* mod, const HfDifficulty* difficulty)`. Adds difficulty level 11 (see HfDifficulty). Call it from hellforge_mod_init. Returns 11, or 0 (the mod's log says why). One mod can add it.
- `difficulty_row`: `uintptr_t (uint32_t level)`. The 0x330-byte settings row of a level (1 .. 11) once HellForge has moved the table, or 0. +0 unlock item and +4 level must stay (artifacts/difficulty11/FINDINGS.md names the members known).

### SDK 6

- `register_entity`: `HfRef (HfMod* mod, const HfEntityDef* entity)`. Registers a new entity from its definition block (see HfEntityDef), with the entities its mount carries and the behaviour it runs. Call it from hellforge_mod_init. Registering the same block again returns the same entity. Returns the entity, or 0 (the mod's log says why, with the source line of a field the loader refused).
- `copy_field`: `int (HfMod* mod, HfRef entity, HfRef from, const HfField* field)`. The calls behind definition blocks, for code: each queues a deferred edit, applied whenever the game loads its entity data (at once if it has). An entity a mod added gets a record of its own in the field's component when the call comes from hellforge_mod_init (later, it must own one already); a vanilla entity's record is changed only if no other entity shares it. Another mod (or a stats mod) changing the same field is reported in both mods' logs and modloader.log; the later edit's value stays. 0 queued, 1 refused (the mod's log says why). Prefer the hf_copy, hf_set, hf_tag and hf_mount macros below.
- `set_field`: `int (HfMod* mod, HfRef entity, const HfField* field, const HfValue* value)`
- `set_tag`: `int (HfMod* mod, HfRef entity, uint64_t tag, int present)`
- `mount`: `int (HfMod* mod, HfRef entity, uint32_t slot, HfRef carried)`
- `record`: `void* (HfMod* mod, HfRef entity, const char* component, uint32_t layout, uint32_t size)`. An entity's own record of a component after HF_EVENT_ENTITIES_READY, checked against the layout the mod was built with, or NULL (the mod's log says why). Use hf_record.
- `find`: `uint64_t (uint32_t kind, const char* name)`. Content by name, or 0: vanilla content by its catalog name (find(HF_KIND_ENTITY, "Pelican Transport"); the hellforge_content.h constants have the same ids), or content a mod added by its identity ("skyeshade.pelican-support:pelican_gatling", or the full name it was added under). For names known only at run time (a config file, another mod's content); code that knows the content uses the constants.
- `edit_entity`: `int (HfMod* mod, const HfEditDef* edit)`. Changes an existing entity from a definition block (see HfEditDef). 0 queued, 1 refused (the mod's log says why, with the source line of a field the loader refused).
- `set_live`: `int (HfMod* mod, HfRef target, const HfField* field, const HfValue* value, uint32_t flags)`. Changes a field in the running game (live editing): the same deferred edit as set_field, applied at once and kept for the rest of the session (renewed if the game reloads its data), with the same checks and conflict reports. The target is found by identity every time, never by address: an entity by its resource id (a vanilla one or one a mod added), or a settings table row by its id (HfProjectileSettings: a projectile type; HfDamageInfo: a damage id; HfStratagemSettings: a stratagem type; HfDifficultySettings: a level; the explosion, arc, beam and status tables: their row ids). The mod's next live edit of the same field replaces this one; value NULL undoes it, putting back the value from before it. A record other entities share is changed only with HF_LIVE_SHARED (it changes all of them, as a stats file does). Returns when the change applies (HF_APPLIES_...), or 0 refused (the mod's log says why). Nothing is saved: a live editor saves into a stats file (hellforge-stats.json).
- `get_live`: `int (HfMod* mod, HfRef target, const HfField* field, HfLiveValue* out)`. Reads a field of the running game, found as set_live finds it (a shared record too): its value now and its base. Returns when a change to it applies (HF_APPLIES_...), or 0 when it cannot be read (no such record, or its table is not loaded yet).
- `set_passives`: `int (HfMod* mod, uint32_t armor, uint32_t second)`. Overrides the local player's armor passive and second passive (the helmet's slot), solo only: the game's attribute reader takes the armor passive's bonuses first, then the second's that the armor lacks. The override is kept (written again after a kit change) until both are HF_PASSIVE_KIT; with other players in, the kits' values return and it waits. Refused per slot, and said in get_passives' status: a passive whose effect needs a package (INTEGRATED EXPLOSIVES, ADRENO-DEFIBRILLATOR) unless the armor gives it, INTEGRATED EXPLOSIVES as the second. Returns 1 held (or released), 0 for an id the game has no passive for.
- `get_passives`: `int (HfMod* mod, HfPassives* out)`. The local player's passives now; returns 1 when the record is readable (the status says why not).
- `on_game_thread`: `int (HfMod* mod, HfTickCallback callback, void* user)`. Calls back every game update on the game thread (the thread the game's own engine calls come from: sounds, spawns, package requests), before the game's update. Keep it short; it runs every frame. Returns 1, or 0 when the game thread's update could not be hooked (modloader.log says why). Check hf->size before calling.
- `load_package`: `int (HfMod* mod, uint64_t package)`. Loads a package (by its resource name hash, as mappings/references.json lists them) and holds it for the session, through the game's own package system on the game thread: HF_PACKAGE_RESIDENT once the engine has all of it, HF_PACKAGE_LOADING until then (call it again to see), 0 refused or failed (not a catalogue package, HellForge's 64 held already, or not loaded within 90 seconds; the mod's log says why). Loading is per client: other players load their own. A reference set_live or a stats file writes (a donor projectile, an explosion) loads its packages itself.
- `last_log`: `const char* (HfMod* mod)`. The mod's last log line (say, why the call that just returned 0 was refused), and the session's logs folder (UTF-8: modloader.log and every mod-<id>.log), or "". Check hf->size before calling.
- `logs_folder`: `const char* (HfMod* mod)`
- `get_stat`: `int (HfMod* mod, const HfStat* stat, HfLiveValue* out)`. A stats field's value now and its base (HfLiveValue's), for any field the session's stats snapshot reads, the fields get_live cannot (entity deltas, say). 1 when read, 0 not (not in the snapshot, or not read yet).
- `session`: `void (HfMod* mod, HfSession* out)`. The session's co-op role (HfSession), as the session's backend tells the loader.

### SDK 7

- `subscribe`: `int (HfMod* mod, uint32_t kind, HfListener listener, void* user, int32_t priority)`. Listens to one kind of game event (HF_ON_..., see HfEventInfo), on the game thread, highest priority first (equal priorities in subscription order). Call it from hellforge_mod_init. Returns 1, or 0 (the mod's log says why: an unknown kind, or the game thread not hooked). A kind's source is hooked once a mod listens to it; one that does not read as reviewed on this game build delivers nothing, and modloader.log says so.
- `game_state`: `uint32_t (HfMod* mod)`. The game's state now (HF_STATE_...), or HF_STATE_NONE before the game has one.
- `content`: `int (HfMod* mod, uint32_t index, HfContent* out)`. The index-th piece of content mods added (stratagems, entities, projectiles, damage; see HfContent): 1 with *out filled, 0 past the last. Complete once every mod's hellforge_mod_init has run (from HF_EVENT_GAME_LOADED).
- `add_ability`: `uint32_t (HfMod* mod, const HfAbility* ability)`. Adds a new ability (see HfAbility). Call it from hellforge_mod_init. Returns its id (2868 and up), or 0 (the mod's log says why). An entity naming it never sets it off if HellForge could not install it (modloader.log).
- `add_stratagem_category`: `uint32_t (HfMod* mod, const HfStratagemCategory* category)`. SDK 8: returns a selection-category handle, or 0 with a logged reason. Re-registering an identical fully qualified definition returns the same handle; a conflicting title/order is refused.

### SDK 9

- `set_stat`: `int (HfMod* mod, const HfStat* stat, const HfValue* value, uint32_t flags)`. Changes a stats field set_live cannot reach (an entity delta: an attachment's or a default magazine's stats; a status multiplier), the fields get_stat reads, live, in the place a stats file writes it at boot. value NULL: back to its value from before this session's live change, or with HF_LIVE_BASE to its base (get_stat's). Returns HF_APPLIES_RESPAWN (a weapon takes an attachment's value when it is next built, expected) or 0 (the mod's log says why). Check hf->size before calling.
- `copy_row`: `int (HfMod* mod, const char* table, uint64_t row, uint64_t from, uint32_t offset, uint32_t size)`. A settings row's bytes (offset, size) replaced live by another row's of the same table, for the rows HellForge's catalogue names (mappings/references.json "rowCopies": the G-109 Urchin's pulse explosion), from the donors listed there, once the donor's packages are resident (it waits for them). from 0 puts the row's own bytes back. Returns HF_APPLIES_NOW or 0 (the mod's log says why). Check hf->size before calling.

### SDK 10

- `mods`: `int (HfMod* mod, uint32_t index, HfModInfo* out)`. The index-th mod of the session (HfModInfo): the code and stats mods in load order, then the Lua mods as they register through the Lua bridge (docs/lua-bridge.md). 1 with *out filled, 0 past the last. Check hf->size.

### SDK 11: actions (HF_ACT_...; check hf->size before calling)

- `heal`: `int (HfMod* mod, float amount)`. Heals the local Helldiver by `amount` health (each limb by the same share), up to its maximum.
- `heal_limb`: `int (HfMod* mod, uint32_t limb)`. Heals one of the local Helldiver's limbs (HF_LIMB_...) in full, and mends it.
- `injure`: `int (HfMod* mod, uint32_t limb, int32_t damage)`. Damages one of the local Helldiver's limbs (1 .. its maximum: head 85, chest 60, arms 35, legs 45); it may down or kill the Helldiver, as the game's own hit would.
- `limb_state`: `int (HfMod* mod, uint32_t entity, uint32_t limb, HfLimbState* out)`. A Helldiver's limb now: its health, maximum and whether it is injured (any Helldiver this machine has).
- `apply_status`: `int (HfMod* mod, uint32_t entity, uint32_t status, float buildup)`. Applies a status (HF_STATUS_...) to an entity: `buildup` 0 .. 1000 (100: as a full hit); host.
- `add_velocity`: `int (HfMod* mod, const float delta[3])`. Adds to the local Helldiver's velocity (m/s, world space, Z up; each part at most 25, the result at most 50). Walking resets sideways speed every update: an upward push is the dependable one.
- `resupply_from_pack`: `int (HfMod* mod)`. The local Helldiver uses its B-1 Supply Pack on itself, as the game's own input does (one supply).
- `spawn_explosion`: `int (HfMod* mod, uint32_t type, const float position[3])`. An explosion (its ExplosionSettings row) at a position, credited to this machine's player; host. Loads the explosion's packages first (HF_ACT_WAITING until they are in).
- `spawn_projectile`: `int (HfMod* mod, uint32_t type, const float position[3], const float direction[3])`. A projectile (its ProjectileSettings type) fired from a position along a direction, as the local Helldiver's; host. Loads its packages first.
- `credit_to_player`: `int (HfMod* mod, uint32_t entity)`. The kills of an entity (a turret, a vehicle a mod spawned) credited to its owner, this machine's player; solo host.
- `freeze_mission_timer`: `int (HfMod* mod, int frozen)`. Pauses (1) or resumes (0) the mission timer; host. A new mission starts it again.
- `spawn_pelican`: `int (HfMod* mod, const HfPelicanCall* call, uint32_t* entity)`. Calls in a transport Pelican (HfPelicanCall); *entity its entity. Host.
- `modify_shots`: `uint32_t (HfMod* mod, const HfShotRule* rule)`. Shot rules: an id (1 and up), or 0 refused. stop_shots ends one (later shots fly as the game makes them). One rule of each kind per projectile type.
- `homing`: `uint32_t (HfMod* mod, const HfHoming* rule)`
- `stop_shots`: `int (HfMod* mod, uint32_t id)`

### SDK 12

- `notice`: `void (HfMod* mod, HfNotice* out)`. HellForge's latest message for the player (HfNotice), as the session's backend posts it. Check hf->size.

### SDK 13

- `hook_ex`: `int (HfMod* mod, uintptr_t target, void* detour, void** original, int32_t priority)`. hook with an order: a function's hooks run first to last, each calling the next through its original. Mods' hooks run first, the highest `priority` first; equal priorities by load order, the mod higher on the Mods page first (a mod's own later hook on the same function before its earlier one). HellForge's own hooks (its events, the registry, the game thread) run last, nearest the game's code. The mod's log and modloader.log name each hook with its place in the chain, a function hooked by more than one mod or by HellForge too is logged as a shared hook with every owner in order, and the session folder's hooks.tsv lists every chain. Refused (1, the mod's log says why): the same detour on the same function twice, more than 16 hooks on one function or 1024 hooked functions in all. Check hf->size before calling.
- `code_matches`: `int (uintptr_t address, const char* pattern)`. 1 when the bytes at `address`, as they were before any hook HellForge placed (its own or a mod's), match the IDA-style pattern ("48 8B ?? 24"); 0 otherwise or when they cannot be read. The check to make before hooking a function: another mod that hooked it first does not fail it, where find_pattern and read would (they see the hook's jump). Only hooks are seen through: bytes a mod changed with write, or that HellForge rewrote, read as they are now. Check hf->size before calling.
- `read_code`: `int (uintptr_t address, void* buffer, size_t size)`. Like read, with the bytes as they were before any hook HellForge placed (as code_matches reads them). 0 on success.

### SDK 14: mod sync (HfSyncState; check hf->size before calling)

- `sync_state`: `int (HfMod* mod, HfSyncState* out)`. The current offer: 1 with *out filled (at most out->size bytes), 0 none (solo, or no backend connected).
- `sync_mod`: `int (HfMod* mod, uint32_t index, HfSyncMod* out)`. The index-th mod of the current offer: 1 with *out filled (at most out->size bytes), 0 past the last.
- `sync_answer`: `int (HfMod* mod, uint32_t version, uint32_t answer, const char* mod_id)`. Sends the player's answer (HF_SYNC_ACCEPT ...) to the offer of that version; mod_id names the mod for HF_SYNC_BLOCK, HF_SYNC_TRUST and HF_SYNC_OPEN (NULL otherwise). 1 sent; 0 not (another offer came since, or no backend connected).

### SDK 15

- `stats_source`: `uint32_t (HfMod* mod)`. Whose stats the lobby plays with: HF_STATS_HOST or HF_STATS_OWN (see HF_STATS_OWN). Check hf->size.

## Components

Entity component records. In a definition block, `HF_FIELD(Component, field)` names a field; for an entity's own
record, `hf_record(mod, entity, HfComponent)` gives a typed pointer (both in `hellforge_mod.h`). Each entry starts
with the game's name for the component, its component number and its record size, then lists its fields:

- Offset: where the field starts in the record, in bytes.
- Type: `u8`, `u16`, `u32`, `i32`, `f32`, `u64` or `bytes`, with a count in brackets for an array.
- Applies: when a live change takes effect in a running game. `now` is the next time the game reads it, `respawn`
  when the entity is next made (a spawn, a re-equip, the next call-in), `mission` when a mission loads. A `?` means
  inferred, not yet confirmed.
- Meaning: what the field does. "(unverified)" marks a field named from research but not yet confirmed in the game;
  "(a projectile reference)" and the like mark a field whose value is a row of that table.

Each component's layout is the game build its offsets were reviewed on. The loader refuses fields of a layout it
does not have, so a mod built against another layout is reported instead of run.

See also: [Content](modding/content.md) for changing existing content by field name, [Logic at run
time](modding/runtime.md) for live edits, [Stats mods](modding/stats-mods.md) for number changes without code, and
[Debugging](modding/debugging.md) for why a field was refused.

## Settings tables

a component number.

See also: [Content](modding/content.md) for settings rows and their row functions, [Logic at run
time](modding/runtime.md) for live edits, and [Stats mods](modding/stats-mods.md) for projectiles, damage, explosions
and statuses without code.
